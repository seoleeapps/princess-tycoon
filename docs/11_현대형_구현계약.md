## 4. 활동 데이터 계약

```json
{
  "id": "EDU_LITERATURE",
  "kind": "education",
  "name": "왕립 교양학",
  "description": "읽고 토론하며 사고와 소통을 기른다.",
  "durationSlots": 1,
  "baseCost": 150,
  "baseReward": 0,
  "energyDelta": -8,
  "stressDelta": 6,
  "risk": 0.0,
  "primaryStat": "intelligence",
  "gains": { "intelligence": 12, "communication": 6 },
  "fixedDeltas": {},
  "requires": {},
  "tags": ["study", "indoor", "academic"]
}
```

- 모든 필드 필수. 수치가 없으면 0 또는 빈 객체/배열을 명시한다.
- `requires` 연산자는 `gte`, `lte`, `worldTier`, `season`, `flags`, `stage`만 허용한다. `stage`는 활동이 처음 열리는 해금 단계(1~7)이며 모든 활동에 명시한다. 1단계 활동은 `EDU_ETIQUETTE`, `EDU_LITERATURE`, `EDU_DOJO`, `REST_HOME`, `REST_WALK`이고, 2단계는 `JOB_CARE`, `JOB_RESTAURANT`, `JOB_HOUSEKEEP`, 4단계는 나머지 학습·아르바이트·휴식과 `CH_EXAM_ACADEMY`, 6단계는 모험과 나머지 도전이다.
- `durationSlots`는 1~6, `risk`는 0~1, `energyDelta`는 -40~100, `stressDelta`는 -100~30.
- 도전 항목은 `challengeWeights`, `baseDifficulty`, `rewardTable`을 추가한다.
- 모험 항목은 `nodes=3`, `enemyPool`, `lootTable`을 추가한다.

### 4.1 해금 단계 데이터 계약

`godot/data/unlocks.json`의 `stages`는 1부터 연속인 7개 항목이다. 각 항목은 `stage`, `when`(`activities` 완료 활동 수 이상, `slot` 날짜 이상, `seasonReviews` 시즌 심사 횟수 이상 중 0~1개), `features`, `label`, `tips`를 가진다. 조건은 단계 순서대로 단조 증가한다.

| 기능 ID | 단계 | 엔진 규칙 |
|---|---:|---|
| `home`, `activity` | 1 | 없음 |
| `plan`, `growth` | 3 | 없음(화면) |
| `challenge` | 4 | 시험 자동 참가는 해당 활동의 `requires.stage`로 판정 |
| `record`, `contracts` | 5 | 5단계 전에는 계약을 생성·추적하지 않는다 |
| `world`, `shop`, `events`, `relations` | 6 | 6단계 전에는 이벤트를 생성하지 않고 난수도 쓰지 않는다 |
| `rules`, `bannedTags`, `customWeights`, `league` | 7 | 없음(화면) |

- 시즌 심사 횟수는 `floor(time.slot / slotsPerSeason)`으로 계산한다.
- 엔진은 slot 해결 직후(시즌 심사 전) 단계를 갱신하고, 같은 호출에서 열린 단계를 결과의 `newUnlocks`로 돌려준다.

## 8. 절차 생성 계약

```text
contentSeed = hash64(saveSeed, worldTier, seasonIndex, slotKind)
contract = weightedPick(template where requirements are satisfiable)
modifierCount = clamp(1 + floor(worldTier/4), 1, 4)
reward = baseReward(template) × 1.13^(worldTier-1) × (1 + 0.18×modifierCount)
```

- 생성 순서는 계약 3개 → 라이벌 5명 → 지역 변형 1개로 고정한다.
- 동일 seed/tier/season은 직렬화 여부와 무관하게 같은 결과를 내야 한다.
- 현재 해금된 활동으로 달성할 수 없는 요구조건은 생성하지 않는다.
- 최근 8개 템플릿의 선택 가중치는 기본의 20%다.
- 생성 이름은 접두 12 × 분야 8 × 목적 10 조각 이상으로 구성한다.

## 9. BigValue 계약

```json
{ "mantissa": 3.141592, "exponent": 42 }
```

- 0은 `{0,0}`.
- 0이 아니면 `1 <= abs(mantissa) < 10`으로 정규화한다.
- 비교, 더하기, 빼기(음수 결과 금지), 실수 배율, 정수 거듭제곱, 축약 표기를 제공한다.
- 지수 차가 16 이상인 덧셈은 큰 값을 그대로 반환해도 된다.
- 저장 왕복 후 mantissa 상대 오차 `1e-9` 이하.
- 세계 티어 10,000의 비용 계산에서 `INF`, `NaN`, 음수가 나오면 실패다.

## 11. 인수조건

### 코어/결정성

- **AC-CORE-01** 같은 seed·상태·정책으로 1,000 slots를 두 번 실행하면 상태 해시가 같다.
- **AC-CORE-02** 모든 스탯·미터·BigValue에 `NaN/INF`가 없다.
- **AC-CORE-03** 에너지·스트레스는 0~100으로 클램프된다.
- **AC-CORE-04** 세계 티어 10,000의 비용·보상·표기가 유효하다.

### 자동 플래너

- **AC-PLAN-01** 잠금(해금 단계 포함)/금지/비용/예산 제약을 어기는 활동을 선택하지 않는다.
- **AC-PLAN-02** 에너지<20 또는 스트레스≥maxStress면 회복 활동을 선택한다.
- **AC-PLAN-03** 후보가 없으면 `REST_HOME`을 선택한다.
- **AC-PLAN-04** 정책 변경은 다음 활동 선택부터 반영된다.
- **AC-PLAN-05** 선택한 활동과 선택 이유 상위 3개가 UI에 표시된다.
- **AC-PLAN-06** 지정 도전과 다음 시즌 도전을 장기 활동·자동 큐가 덮지 않으며, 참가 지원 예외가 결정적으로 적용된다.

### 활동/경제

- **AC-ACT-01** 43개 기본 활동 ID가 중복 없이 로드된다.
- **AC-ACT-02** 비용 활동은 잔액을 음수로 만들지 않는다.
- **AC-ACT-03** 보수·성장·스트레스·에너지가 문서 10 공식과 seeded jitter를 따른다.
- **AC-ACT-04** 활동 숙련과 최근 8개 기록이 정확히 갱신된다.
- **AC-ACT-05** 15학습/11알바/4휴식/5모험/8도전 분류 수가 일치한다.

### 방치/저장

- **AC-IDLE-01** 오프라인 8시간 초과는 28,800초만 정산한다.
- **AC-IDLE-02** 시계 역행은 0 slot, 손실 없는 저장, 경고 기록으로 처리한다.
- **AC-IDLE-03** 같은 slot 수를 온라인/오프라인 리듀서로 실행하면 같은 결과다.
- **AC-IDLE-04** `autoRun=false`이면 오프라인 slot은 진행되지 않으며, 이벤트 만료는 각 60초 경계에서 온라인과 같은 순서로 처리된다.
- **AC-SAVE-01** v2 세이브 라운드트립 상태 해시가 같다.
- **AC-SAVE-02** 손상된 본 파일은 `.bak`으로 복구하고 손상본을 보존한다.
- **AC-SAVE-03** v1 세이브는 이름·스탯·골드·도감을 보존해 v2로 마이그레이션한다.
- **AC-SAVE-04** 원자 저장 실패는 메모리 상태와 기준시각을 원복하며, 시계 역행 저장은 미래 기준시각을 보존한다.

### 모험/도전/생성

- **AC-WORLD-01** 모험 3노드에 승리·패배·강제 휴식 분기가 있다.
- **AC-WORLD-02** 시험/스포츠/대회 8종이 서로 다른 평가 가중치를 사용한다.
- **AC-WORLD-03** 같은 seed/tier/season은 같은 계약 3개·라이벌 5명·지역 변형을 만든다.
- **AC-WORLD-04** 생성 계약은 현재 상태에서 달성 가능하다.
- **AC-WORLD-05** 최근 템플릿 반복 억제가 실제 선택 가중치에 반영된다.
- **AC-WORLD-06** 라이벌 강점·약점·성격과 도전별 점수가 실제 판정에 반영되고 초기·장기 시즌 표본 승률이 35~80%다.

### 단계적 해금

- **AC-UNLOCK-01** 새 게임에서 탭은 홈·활동 2개, 활동은 5개만 보이고, 다음 단계 예고는 1개(2단계가 아르바이트를 열므로 활동 목록 끝)다.
- **AC-UNLOCK-02** 활동 3회·8회, 14일째, 시즌 심사 1·2·3회에 해당 단계가 열리고 내려가지 않는다.
- **AC-UNLOCK-03** 플래너·즉시 1회·자동 큐는 열리지 않은 활동을 고르거나 실행하지 않는다.
- **AC-UNLOCK-04** 이벤트는 6단계 전, 계약은 5단계 전, 시험 자동 참가는 4단계 전에 생기지 않는다.
- **AC-UNLOCK-05** 같은 seed·입력은 온라인 진행과 오프라인 정산에서 같은 날 같은 단계와 같은 상태 해시를 만든다.
- **AC-UNLOCK-06** 오프라인 정산으로 열린 단계는 정산 시트의 "새로 열림" 목록에 보이고 알림 띠는 뜨지 않는다.
- **AC-UNLOCK-07** `unlocks`가 없는 기존 저장은 진행값으로 단계를 계산하고 알림·안내를 띄우지 않는다.
- **AC-UNLOCK-08** 설정·접근성·저장·이어하기·새 수련생·일시정지는 1단계에서 쓸 수 있다.
- **AC-UNLOCK-09** 새 단계마다 "새로 열림" 1회(그 진행에서 끝난 결과가 있으면 결과 창의 첫 줄, 자동 진행이어도 한 줄 띠 대신 결과 창. 끝난 결과가 없으면 알림 띠), 해당 화면 첫 진입 안내 1회를 보여 주고 재실행 뒤 다시 띄우지 않는다.
- **AC-UNLOCK-10** 성장 방향 8종 모두 84일째 7단계에 도달하고, 112일 능력치 합이 `f67378a` 기준의 90% 이상이며 활동이 멈추지 않는다.
- **AC-UNLOCK-11** 단계 1~7의 모든 화면에서 필수 CTA가 잘리지 않고 짝수 격자와 대비를 지킨다.
- **AC-UNLOCK-12** 현재 활동 이유 줄에 아직 열리지 않은 개념이 나오지 않는다.

### 이벤트/관계/상점

- **AC-CONTENT-01** 이벤트 26개, 상점 21개, 진로 칭호 38개가 중복 없이 로드된다.
- **AC-CONTENT-02** 활동당 이벤트 큐 추가는 최대 1건, inbox는 최대 20건이다.
- **AC-CONTENT-03** 미응답 선택 이벤트는 기본 선택으로 해결 가능하다.
- **AC-CONTENT-04** 인벤토리 중첩 99, 판매가 50%, 장비 4슬롯 규칙을 지킨다.
- **AC-CONTENT-05** 칭호 획득은 게임을 종료하거나 상태를 초기화하지 않는다.
- **AC-CONTENT-06** 38개 칭호의 별 값은 반복 심사로 증가한다.
- **AC-CONTENT-07** 관계는 활동 성장, 선물, 계약 생성·완료, 칭호 표시 변형에 연결되고 아르바이트 위험 사건은 결과에 노출된다.

### UI/런타임

- **AC-UI-01** 새 게임→정책 설정→자동 활동→결과→저장→이어하기 경로가 동작한다.
- **AC-UI-02** 홈/계획/활동/성장/월드/기록/상점/설정/오프라인/이벤트의 12개 기능 경로에 해당 해금 단계가 열린 뒤 도달 가능하다.
