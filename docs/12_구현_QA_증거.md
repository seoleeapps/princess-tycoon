### 화면 좌표 E2E 여정

`npm run test:e2e`는 실제 `main.tscn`을 390×844, 430×932, 720×1280 SubViewport에 띄우고, 버튼 중심 탭과 목록 드래그만으로 화면을 이동한다. 함수 직접 호출로 화면을 건너뛰지 않는다. 바꾸는 것은 플랫폼 경계 두 개뿐이다.

- 저장: `princess_tycoon/testing/save_path`로 `user://e2e/<viewport>/save.json`에 격리한다.
- 시계: `princess_tycoon/testing/fixed_unix`로 1,800,000,000에 고정하고, 복귀 시나리오에서 7,200초(오프라인 120일, 해금 7단계를 넘김)를 앞당긴다. 화면의 시각 판단은 모두 `main_screen.gd`의 `_now_unix()`를 지난다.

| 시나리오 | 이어지는 경로 |
|---|---|
| `first-session` | 홈 → 메뉴 → 새 수련생(이름 입력·균형 방향, 해금 1단계) → 설정(모션 줄이기·고대비) → 활동 1회 실행 반복으로 2단계(아르바이트)·3단계 → 활동 상세에서 자동 큐 추가 → 계획(학문 방향) → 성장 → 현재 활동 상세 → 일시정지·재개 → 저장 |
| `return-offline` | 장면 해제 → 2시간 뒤 재실행 → 이름·방향 복원 → 오프라인 정산 받기(7단계) → 월드 원정과 시트 위 결과 창 → 계획 스테퍼 → 활동 목록 드래그 스크롤과 자동 갱신 뒤 위치 유지 → 기록 → 상점 구매 → 이벤트 선택 → 이어하기 |

2026-11-05 단계적 해금 뒤 Godot 4.7.2 headless 실행에서 세 viewport 모두 `first-session` 60/60, `return-offline` 74/74 단계가 통과했다. 단계적 해금으로 첫 세션은 1~3단계만 지나고, 월드·기록·상점·이벤트·세부 규칙 경로는 오프라인 정산으로 7단계를 연 복귀 여정으로 옮겼다. 그 전(픽셀 UI 개편 뒤)에는 84/84, 21/21이었다. 개편으로 계획 스테퍼, 활동 상세 시트의 자동 큐 추가, 고대비 전환, 자동 진행 뒤 목록 스크롤 유지, 결과 창을 눌러 닫기(시트 위 포함), 구매 뒤 상점 스크롤 유지, 현재 활동 상세, 정산 변화 목록과 홈 다시 그림 단계가 더해졌다. 독립 검수 3회 기록은 `game-design/ui/review/round-1~3.md`에 있다. 결과는 `build/e2e/<viewport>/journey.json`에 남는다. `npm run capture:e2e`는 같은 여정을 렌더링 모드로 돌려 장면별 PNG 22장을 저장한다.

여정을 처음 붙이면서 두 결함을 찾아 고쳤다.

- 목록 카드의 버튼과 패널이 입력을 멈춰(`MOUSE_FILTER_STOP`) 카드 위에서 시작한 드래그로는 목록이 스크롤되지 않았다. 스크롤 내용의 버튼·카드·칩·토글을 `MOUSE_FILTER_PASS`로 바꿨다. 드래그가 활동을 실행하지 않는지도 여정에서 확인한다.
- 엔진 상태를 화면 상태로 받을 때 엔진이 없을 때 쓰는 데모 값과 합쳐, 새 수련생에게 얻지 않은 숙련(14·8·6), 진로 칭호 "왕립 연구자 ★1", 가짜 최근 결과가 보였다. 진행 기록 항목을 비운 `_engine_state_shape()`를 기준으로 합치도록 고쳤다.

## 3. 결정성·장기 성장·밸런스

- 같은 seed·초기 상태·정책으로 1,000 slot을 두 번 실행한 상태 해시가 일치했다.
- 세계 티어 10,000에서도 비용·보상·표기와 BigValue가 유효했다.
- 시즌 1, 10,000, 1,000,000의 5단계 라이벌 표본 승률은 40.0~76.7%로 계약 범위 35~80% 안에 있었다.
- 반복 시즌 심사에서 38개 진로 칭호를 얻은 뒤에도 별과 세계 티어가 계속 증가하고 게임이 종료되지 않았다.
- 계약 생성은 진행 중 활동, 예정 도전, 회복, 반복 비용, 스트레스, 관계 상한, modifier를 같은 시즌 타임라인으로 계산한다. 도전 승리 계약은 예정 완료 slot의 런타임과 공유하는 exact jitter, 선행 경기로 도달 가능한 리그 상대 점수, 기본 난이도 floor를 함께 검사한다. 64개 seed/state 행렬과 마지막 슬롯 실제 reducer 반례를 통과했다.

고정 seed `20260714`, 1 slot=1 게임 일 기준 밸런스 결과다.

| 시점 | 완료 활동 | 골드 | 에너지 | 스트레스 | 명성 | 총 능력치 |
|---|---:|---:|---:|---:|---:|---:|
| 1일 | 1 | 2.54K | 88 | 8 | 0 | 936.61 |
| 7일 | 6 | 1.94K | 14 | 54 | 0 | 1,040.62 |

각 체크포인트는 시간 진행, NaN/INF 부재, 상태 불변식, BigValue 유효성, 활동 정체 없음 조건을 통과했다.

## 4. 실제 모바일 렌더

아래 이미지는 headless dummy가 아니라 Godot GL Compatibility 런타임으로 메인 씬을 실제 렌더해 저장했다. `render_capture.gd`는 390×844 좌표계를 기기 해상도에서 직접 그린다(`size_2d_override`). 글자와 도트를 확대하지 않고 기기 배율로 래스터하므로 정수가 아닌 배율의 도트 굵기까지 실제 기기와 같게 보인다. 2026-11-04 픽셀 UI로 다시 렌더했다.

- [390×844 논리 기준 화면](qa/mobile-390x844.png)
- [1170×2532 휴대폰 3배](qa/device-1170x2532.png)
- [1290×2796 대형 휴대폰 3배](qa/device-1290x2796.png)
- [720×1280 안드로이드 1.52배](qa/device-720x1280.png)
- [390×844 활동 결과 창](qa/result-feedback-390x844.png)

```bash
for size in 1170x2532 1290x2796 720x1280; do
  $GODOT_BIN --path godot --script res://tests/render_capture.gd -- \
    --size=$size --output="$PWD/docs/qa/device-$size.png"
done
$GODOT_BIN --path godot --script res://tests/render_capture.gd -- \
  --size=390x844 --output="$PWD/docs/qa/mobile-390x844.png"
$GODOT_BIN --path godot --script res://tests/render_capture.gd -- \
  --size=390x844 --result-feedback \
  --output="$PWD/docs/qa/result-feedback-390x844.png"
```

다섯 렌더 모두 `[RENDER] PASS`와 정확한 픽셀 크기를 출력했다. 430×932 같은 1.1배 렌더는 실제 기기 해상도가 아니고 픽셀 폰트 획이 깨져 보여 기준 렌더에서 뺐다(430pt 기기는 3배인 1290×2796). 육안 검사에서 방 장면과 수련생, 현재 활동 창, 미터, 행동 버튼, 하단 탭의 잘림·겹침이 없었고 9분할 창의 이음매가 없었다. 결과 창은 상세를 첫 줄 2줄, 나머지 1줄로 줄여 높이 약 210px로 유지된다. 720×1280의 좌우 여백은 390×844 논리 화면을 왜곡하지 않는 `keep` 정책의 의도된 pillarbox다. 시안 비교와 개편 중 캡처 위치는 [실행 화면 비교 기록](game-design/ui/runtime-compare.md)에 있다.

## 5. Web export

`npm run build:web`은 release export에 성공했다. `build/web/`에 HTML, JavaScript, PCK, WASM, worklet, 아이콘이 생성됐다. 2026-11-04 개편 뒤 번들 폰트가 Noto Sans KR(10.4MB)에서 Neo둥근모(0.65MB)와 Galmuri11 Bold(2.6MB)로 바뀌어 PCK가 약 11MB에서 6.07MB로 줄었다.

주요 산출물:

- `index.html`
- `index.js` 약 308KB
- `index.pck` 6.07MB(개편 전 약 11MB)
- `index.wasm` 약 39.5MB(Godot 4.7.2 템플릿)

`build/`는 재생성 가능한 산출물이므로 Git 추적 대상에서는 제외한다.

## 6. 범위 감사

GDD 1차 구현 범위의 자동 플래너, 온라인/오프라인 진행, 43개 활동, 자동 모험 3노드, 8개 도전, 계약·라이벌·지역·적·보상 절차 생성, 이벤트, 관계, 장비, 시즌 심사, 38개 무한 칭호, v2 저장/복구/마이그레이션, 12개 UI 경로, 코드로 만든 도트 아트(페이퍼돌, 배경 5종, 스킨, 아이콘)와 픽셀 폰트, 합성 오디오와 플랫폼 포트를 구현했다. 최신 코드와 문서 계약을 독립 재감사한 결과 실제 gameplay 또는 무한 변형 기능 누락은 0건이었다.

의도적으로 제외한 항목은 GDD 범위 경계와 같다: 원작 런타임 리소스, 유료 생성 API, 실제 광고/IAP SDK, 서버·클라우드 저장·멀티플레이, 스토어 출시. 구현 정본과 계약의 1차 범위에서 남은 미구현 항목은 없다.
