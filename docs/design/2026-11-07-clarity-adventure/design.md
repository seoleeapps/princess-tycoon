# 목표 안내와 모험 장면 — 설계 v1

- 상태: 사람 검토 대기. 공통 홈 개선과 모험 A안을 추천하며, A·B는 아직 선택되지 않았다.
- 기준: main `6232e9c5d177900b830ab20eac3ad1f2d58b50fa`, 기존 아카데미 방 도트 방향 A.
- 승인 대상: 이 문서·비교 시안·같은 폴더의 `test-plan.json`을 포함한 설계 커밋. 구현·검수 후 Ready PR의 main 병합까지다. 이번 설계에는 새 마켓 배포와 기기 사용을 포함하지 않는다.
- 사용자 근거: “뭘 해야하는지 어떻게 돌아가는건지 목표가 뭔지 잘 모르겠더라”, “모험을 떠나면 실제로 모험을 하는 장면이 나오면 좋겠다”.

## 현재 문제와 해결 범위

실제 첫 홈과 월드 원정을 390×844 렌더링 E2E로 확인했다. 첫 홈에는 현재 활동·미터·자동 1회 실행·최근 결과만 있고, 플레이어의 역할과 장기 목표가 없다. 성장 방향은 활동 8회 뒤, 기록과 칭호 안내는 첫 시즌 심사 뒤 열리므로 초반에 육성의 목적이 숨는다. `_build_home_page()`와 `unlocks.json`에서 같은 구조를 확인했다.

모험 규칙은 이미 탐색·중간 조우 또는 사건·보스 3단계다. 그러나 `_run_world_activity()`가 기존 즉시 실행 경로를 부르고, `_resolve_adventure()`가 판정을 한 번에 끝낸 뒤 `_build_adventure_feedback_payload()`가 문구 위주 결과를 만든다. 실제 캡처에서도 원정 성공 창이 목록 위를 덮고 3노드·적 이름이 말줄임으로 잘렸다. 기존 나침반 연출만으로는 이동·조우·전투를 알 수 없다.

이번 변경은 게임의 목표와 인과를 화면에서 보여 주고, 기존 판정에 맞는 모험 장면을 더한다. 43개 활동, 38개 진로 칭호, 해금 조건·시간·승패·경제·광고 및 결제 범위는 그대로다. 목표 카드를 완료해도 새 보상을 지급하지 않는다. 새 3D·직접 이동·공격 조작·온라인 서비스는 도입하지 않는다.

## 시각 자료와 선택

비교 시안은 `render_mockups.py`로 기존 코드 도트·스킨·폰트·캐릭터 합성을 재사용해 만들었다. 재현: `python3 docs/design/2026-11-07-clarity-adventure/render_mockups.py --out build/clarity-adventure/mockups`. 시안은 논리 390×844이며 전투 수치는 설계용 예시다. 실제 구현·동작 검수 증거가 아니다. PNG 원본과 현재 화면은 `evidence.md`의 NAS 위치에 보관한다.

| 대안 | 공통 홈 | 같은 은잎 숲 조우 장면의 구성 | 판단 |
|---|---|---|---|
| A. 장면 중심 | 심사 목표·현재 활동·다음 행동 | 수련생과 적을 크게 배치하고 위에 3단계, HP·실제 피해·전리품을 순서대로 표현 | 추천. 모험하는 장면을 보고 싶다는 요구에 직접 맞는다 |
| B. 탐험 지도 중심 | A와 같음 | 탐색·조우·보스를 잇는 경로에 수련생을 놓고 현재 조우를 지도 위에서 표현 | 이동 경로가 더 잘 보이지만 전투를 보는 면적이 작다 |

화풍·폰트·팔레트·장비 합성은 기존 승인을 재사용한다. 이번 선택은 모험의 화면 구성이다. 서로 다른 팔레트나 전혀 다른 장르를 새로 고르는 절차가 아니다.

## 목표와 첫 세션

플레이어의 역할은 “수련생의 성장 방향을 정하는 사람”, 게임의 진행은 “수련생이 자동으로 활동하고 성장”, 장기 목표는 “원하는 분야의 진로 칭호 수집과 별 성장”으로 설명한다. 최초 안내는 이 세 가지를 실제 화면의 수련생·방향 버튼·심사 목표와 연결해 짧게 보여 주고 메뉴에서 다시 볼 수 있게 한다. 처음부터 긴 설명 시트를 읽게 하지 않는다.

홈에는 목표 카드 하나와 현재 할 일 하나를 둔다. 목표는 실제 상태에서 계산한다. 첫 심사 전에는 `첫 목표 · 시즌 심사 받기`, 현재 일수와 28일까지의 진행을 보여 준다. 첫 심사 뒤에는 수집한 칭호 수와 현재 가장 가까운 진로 조건을 보여 준다. 조건을 채워도 칭호는 기존처럼 심사에서만 받는다. 모든 칭호를 얻은 뒤에는 다음 별 조건으로 바뀐다. 칭호 조건과 진행률은 시즌 기록의 오래된 cache 대신 현재 상태로 계산한다.

| 시점 | 지금 할 일과 화면 반응 |
|---|---|
| 첫 홈 | `수업은 자동 진행돼요`와 완료까지 남은 시간을 수련생 옆에 표시. 기본 버튼은 `활동 살펴보기`, 기존 수동 즉시 실행은 `지금 활동 마치기`로 구분 |
| 활동 3회 전 | `첫 아르바이트 열기 · 활동 N/3회`를 보여 주며 활동 목록으로 연결 |
| 활동 8회 뒤 | 계획이 열렸을 때 `성장 방향 고르기`를 한 번 안내. 선택한 방향이 다음 활동부터 적용된다는 예시를 보여 줌 |
| 14일·28일·56일 | 기존 해금 상태의 다음 목표 하나만 보여 줌. 첫 심사는 28일, 월드는 두 번째 심사 뒤에 열리지만 체력 등 모험 참가 조건을 충족해야 함 |
| 월드가 열리고 첫 모험 전 | 모험 조건을 충족하면 `첫 원정에 도전`, 부족하면 현재/필요 능력치와 준비할 행동을 표시 |
| 그 뒤 | 가까운 칭호·다음 별의 부족 조건과 가능한 다음 행동을 표시. 닫힌 기능을 조작하라고 안내하지 않음 |

현재 활동 이름은 충분한 폭 또는 두 줄을 확보하고 핵심 이름을 말줄임으로 숨기지 않는다. 활동 결과는 실제 성장량과 다음 목표의 변화를 함께 보여 준다. 강제 휴식 때는 자동 선택 이유를 먼저 보여 주므로 플레이어가 목표와 무관하게 움직인다고 느끼지 않게 한다. 기존 새로 열림 알림과 결과 창을 겹쳐 쌓지 않는다.

## 모험 진입과 화면 상태

수동 원정은 기존 참가 조건과 시험 불참 확인을 먼저 통과한 뒤 장면으로 들어간다. 홈에서 자동 모험을 보고 있을 때도 같은 표현기를 쓴다. 자동 원정마다 모달을 강제로 열거나 다른 탭을 빼앗지 않는다. 홈을 떠난 동안의 모든 과거 원정을 줄줄이 재생하지 않는다.

장면은 `지역 진입 → 탐색 → 조우 또는 사건 → 보스 → 전리품·성장 → 다음 준비`로 이어진다. 탐색에는 실제 지도 발견·우회로를, 중간에는 실제 적 또는 회복의 샘·낙석을 보여 준다. 실패하면 보스까지 성공한 것처럼 재생하지 않고 실패한 노드에서 후퇴·부상·다음 휴식 안내로 이어진다. 숲·동굴·유적·화산·균열의 5개 지역과 기존 적 15개 ID를 구분한다. 생성 변형의 실제 이름·특성을 같이 표시하고 장비·성장색은 수련생 뷰의 합성 결과를 재사용한다.

판정은 기존 엔진이 한 번만 실행하고 장면은 그 결과를 재생한다. UI가 난수를 추가 소비하거나 전투를 다시 계산하지 않는다. 현재 노드의 HP·피해·승패는 실제 기록을 사용한다. 기본 재생은 총 8초 안팎을 목표로 하되 긴 전투의 연속 공격은 실제 합계 피해와 최종 HP를 묶어서 표현한다. 이 시간은 제안값이며 구현 후 체감과 측정으로 확인한다. `결과 바로 보기`와 `홈으로`는 항상 쓸 수 있고, 장면 시청 여부가 보상·시즌 진행·자동 진행 속도를 바꾸지 않는다.

앱 비활성·명시적 일시정지에서는 장면 시간도 정지한다. 돌아오면 같은 장면의 이어보기 또는 결과 보기로 복귀한다. 홈 이탈은 새 모험의 강제 재생을 중단한다. 모션 줄이기는 흔들림·이동·피해 숫자 비행을 끄고 정적인 노드·HP·결과를 제공한다. 오프라인 정산은 기존 요약을 우선하고, 최근 모험 하나만 선택해서 볼 수 있다.

## 구조·데이터·실패 처리

- 새 `goal_presenter.gd`: 현재 상태·ContentDB·해금 상태를 받아 목표, 진행, 부족 조건, 이동할 화면을 반환하는 순수 표시 모듈. `_career_gate_result()`의 읽기 계산을 재사용하는 `career_goal_preview()`를 추가하며, 보상과 칭호를 지급하는 `_evaluate_career_titles()`를 표시 목적으로 호출하지 않는다.
- `main_screen.gd`: 목표 카드와 첫 진입 안내, 기존 활동·월드 버튼의 진입과 결과 연결을 담당한다. 엔진 실행과 저장이 성공한 결과 snapshot만 표현기에 전달한다. 장면을 닫거나 다시 보아도 엔진을 호출하지 않는다.
- 새 `adventure_view.gd`와 재생기: 지역·적·기존 수련생 합성·노드 상태·효과를 그린다. 같은 모험을 중복 재생하지 않게 UI 소유 sequence ID를 사용하고 저장·게임 난수와 분리한다. 큰 전투 원본을 UI가 매 프레임 복제하지 않는다.
- `game_engine.gd`: 기존 난수 호출 바로 뒤에서 실제 적용 피해·공격 주체·전후 HP를 기록한 선택적 `outcome.presentation`을 만든다. 탐색·사건·노드 결과도 연결한다. 전투 공식·호출 순서·보상·중간 게임 상태를 바꾸지 않는다. 최대 30턴·실제 수행한 두 전투 범위로 크기를 제한하며 무한 로그를 만들지 않는다.
- 안내 완료 표시는 `settings.guidanceSeen` 배열만 추가한다. 새 게임은 비어 있고 기존 저장은 기존 이용자로 판별해 첫 실행 강제 안내를 생략한다. 기존 정책·이름·장비·해금·진행은 보존한다. 안내는 메뉴에서 다시 열 수 있다.
- v2 저장과 예전 `lastResult`에는 `presentation`이 없을 수 있다. 그 경우 기존 3노드 결과를 정적으로 보여 주고 존재하지 않는 개별 피해를 지어내지 않는다. 형식 오류·필수 아트 누락은 검사에서 실패시키고 사용자 기록을 초기화하지 않는다. 저장 실패 시 성공 연출이나 보상을 중복 표시하지 않는다.

## 아트·소리·품질

기존 코드 도트 제작 경로를 사용해 5지역 배경과 15적 sprite, 탐색·이동·공격·피격·승리·후퇴 상태를 추가한다. 유료 생성 API 예산은 사용하지 않는다. 환경의 기존 촛불·잎사귀, 장비 합성·nearest·아트 1px=논리 2px를 유지한다. 시안의 골렘은 방향 확인용이며 최종 15종 제작·검수는 구현 범위다.

새 목표 카드와 모험 화면의 공통 구성요소는 검수된 game-foundation ui_kit 계약 1.1.0(원본 ca2ff1f22b3b3aa0ffb718639a980d4d4bb5b6b8)의 theme·HUD·팝업·효과음·보상·파티클을 제품용 픽셀 스킨과 연결한다. 공통 코드의 해시를 바꾸거나 기존 게임을 outgame 구조로 자동 전환하지 않는다. 기존 Neo둥근모 본문 16px, Galmuri11 Bold 제목 24px와 그린 스킨을 재사용한다. 실제 조작 영역은 48px 이상, 대비 4.5:1 이상, 390×844·430×932·720×1280에서 잘림과 가림이 없어야 한다. 공격·피격 효과음과 작은 도트 파티클은 장면의 순간 피드백으로, 전리품은 기대·획득·재화 반영의 3단계로 표현한다. 음소거와 모션 줄이기를 따른다.

기존 별도 `ui_gate`가 custom Theme를 읽지 못해 7 FAIL이었던 기록을 새 UI 작업의 통과로 이어받지 않는다. 구현 시 새 구성요소의 서체·스킨·모션·효과음·보상·파티클·HUD·재화 근거를 보고서로 남기고 정적 미판정과 실제 누락을 구분해 해결한다. 관측/백엔드 SDK는 추가하지 않는다.

테스트 계획은 L3/dev, `redesign: true`, 독립 전체 기능 검수 3회다. 작성자가 의미 있는 실패 테스트부터 구현하고, 각 회차는 다른 검수 에이전트가 같은 후보의 전체 기능과 UX를 직접 실행한다. 회차 계획·기대 결과·격리 저장·SHA·시작/완료 시각·스크린샷·판정을 남긴다. 수정 확인과 실패 이력은 보존하고 회차를 통과할 때까지 무한 재실행하지 않는다. 3회 뒤 미완료면 추가 승인 전 멈춘다.

명령은 `npm test`, `npm run test:e2e`, `npm run capture:e2e`, `npm run test:balance`, `npm run build:web`에 새 목표·모험의 순수/런타임/E2E 검사를 추가한다. 종료 코드와 전체 로그의 SCRIPT ERROR·ERROR:·리소스 누락을 검사한다. 아트 시각 품질은 TDD 대신 선택 시안과 실제 렌더·전체 장면 비교로 검수한다. 중앙 계약은 `seorilabs/.github` 원격 SHA `2bf7204159ced1cb0de2644f00485736bfea2173`에서 확인했다. 중앙 조직 전용 릴리스 파이프라인을 이 저장소에 새로 편입하지 않는다.

## 적용·복구·승인

선택 후 목표·안내부터 구현하고, 결과 기록·모험 재생·전 지역 아트를 연결한 뒤 독립 검수 3회와 로컬 코드 리뷰를 거쳐 한국어 Ready PR을 main에 병합한다. 기존 활동 선택·판정·보상은 비교 테스트로 고정한다. 추가한 optional 표시 필드는 이전 코드가 읽지 않아도 진행을 잃지 않아야 하며 문제 발생 시 해당 PR을 되돌릴 수 있게 기존 데이터 키를 지우지 않는다.

지금은 설계와 시안만 작성했다. 제품 실행 코드를 수정하거나 신규 배포하지 않았다. 앞선 1.0.1의 출시 승인을 이 개편의 마켓 제출 승인으로 확대하지 않는다. 이번 완료 지점은 main 병합이며 배포가 필요하면 별도 지시를 현재 설계에 기록한다.
