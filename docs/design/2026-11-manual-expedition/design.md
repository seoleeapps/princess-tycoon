## 목적·범위·근거

플래너는 다음 시험 전에 끝나지 않는 활동을 고르지 않는다(GDD §5, AC-PLAN-06). 모든 시험이 열리면 시즌에서 가장 긴 빈 구간이 3칸(1~3일째)이다. 그래서 붉은 능선 원정(4칸)과 청람 균열 관문(6칸)은 고를 날이 없다.

붉은 능선 원정은 조건(체력 220, 전투 180, 세계 티어 3)이 개척 원정 리그와 같다. 그래서 열리는 순간부터 막힌다. 이슈 #12의 검수 기록에서는 티어 6, 능력치 600으로 56칸을 보는 동안 두 원정을 고를 수 있는 날이 0일이었다.

| 범위 | 제외 |
|---|---|
| 원정(모험 5종)의 직접 실행(월드 시트 "원정 시작", 활동 탭 모험 행 "1회", 활동 상세 "이 활동 1회")은 시험 일정보다 먼저 한다 | 자동 진행, 자동 큐, 오프라인 정산의 시험 우선 규칙(그대로) |
| 겹친 시험은 그 회차에 참가하지 않는다. 다른 불이익은 없다 | 학습·알바·휴식의 직접 실행(그대로 시험 우선) |
| 겹칠 때 카드·행·상세에 겹치는 시험을 알리고, 월드 카드와 상세 버튼은 "시험 빠지고 출발"로 바꾼다. 출발하면 불참한 시험을 알림으로 알린다 | 확인 시트, 시험 일정·원정 길이 변경 |
| 해금 단계, 능력치·세계 티어 조건, 금지 태그, 회복 강제, 비용·최소 보유금은 그대로 지킨다 | 밸런스 수치 변경 |

## 규칙

- 직접 실행한 원정은 시작 판정과 큐 선택에서 "예정 도전 우선" 규칙 하나만 빼고 판정한다(`Planner.rejection_reason(state, activity, allow_exam_overlap)`). 엔진은 직접 실행 중인 원정 id를 실행이 끝날 때까지만 기억하고 저장하지 않는다.
- 원정은 지금 진행 중인 활동이 끝난 다음 칸에 시작한다. 그 시작부터 원정 길이 동안 시작하는 시험이 "빠지는 시험"이다(`Planner.schedule_conflicts`). 직접 실행 결과에는 `skippedChallenges`(시험 id)를 담는다.
- 정해진 날 시험을 고르는 다른 경로(자동 진행, 오프라인)는 그대로라, 같은 seed와 같은 입력은 같은 결과를 만든다.

## 화면

| 위치 | 겹칠 때 표시 |
|---|---|
| 월드 시트 원정 카드 | 설명 아래 강조색 줄 "24일째 개척 원정 리그와 겹쳐요. 출발하면 그 시험에 빠져요", 버튼 "시험 빠지고 출발" |
| 활동 탭 모험 행 | 비용 줄 대신 강조색 "24일째 시험에 빠져요", "1회" 버튼은 누를 수 있음 |
| 활동 상세 시트 | 강조색 줄(월드 카드와 같은 문구), 실행 버튼 "시험 빠지고 1회" |
| 출발 뒤 알림 | "붉은 능선 원정 1회를 해결했어요." 다음 줄 "개척 원정 리그에는 불참했어요." |

겹치는 시험이 둘 이상이면 첫 시험 이름 뒤에 "외 N개"를 붙인다. 잠금(능력치 부족 등)이 있으면 지금처럼 잠금 줄과 막힌 버튼을 보인다.

## 테스트 계획

L3, 개발 환경(Godot headless와 렌더링), 기기 사용 없음. `npm test`, `npm run test:e2e`, `npm run capture:e2e`, `npm run test:balance`, `npm run build:web`을 돌린다. 자동 진행 결과가 바뀌지 않는지는 해금 진행 측정(112일 능력치)과 밸런스 상태 해시로 본다. 다른 에이전트가 1회 독립 검수한다. 끝 지점은 main 병합이다.
